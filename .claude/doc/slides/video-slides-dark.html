Why

Every product that lives on external data fights the same battle

  • Sites actively block scrapers
  • Every source has its own structure and its own protections
  • The question: add a new source — rewrite the core, or just plug in a new module?

What

A production-style data ingestion pipeline

  • Messy, protected external sources → clean, searchable, deduplicated data
  • 4 real sources. 4 different problems. 1 interface.

Input

Input is deliberately hostile

  • Plain HTML · RSS feeds · JS-rendered pages · Cloudflare · browser fingerprinting
RemoteOK
Cloudflare — a normal request gets 403
Habr Career
Server-rendered, extra JSON-LD calls per vacancy
WeWorkRemotely
Fingerprints the browser after the first hop
Craigslist
Generic classifieds — filtered by category, fanned out by city

Stack & Processing

One CrawlStrategy interface, two fetch strategies

  • Modeling a real production data-ingestion approach — not a toy script
  • Axios + Cheerio for simple cases
  • Puppeteer with a real browser fingerprint when we need to look human
  • Every strategy maps its raw response into one shape — RawVacancy — before anything touches the database
  • Redis: per-source rate limiting with jitter + 1-hour TTL cache for raw pages

Index & Search

One upsert, always deduplicated

  • Dedup key: sourceId + externalId — re-crawls never create duplicates
  • Schema is versioned — an incompatible change rebuilds the index
  • Facets: specialization, seniority, remote/on-site, location, company
  • Full-text search + autocomplete from the second character

Result

The architecture holds

  • Same interface across four completely different sources
  • Anti-bot protections bypassed live, not in theory
  • Real data in seconds
  • Search behaves like production
  • Ready to extend — a new source is a new strategy, not a rewritten core
